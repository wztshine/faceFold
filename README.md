# face-video-group

将包含**相同人脸**的视频自动归入同一个文件夹。基于 insightface（ArcFace/buffalo_l）做人脸检测与特征提取，把含有同一个人（或同一组人）的视频归类整理。

支持**断点续跑**（中断后自动跳过已处理视频）、**增量分类**（新增视频自动匹配已有分组）、**分组最少视频数**（同一人 ≥ N 个视频才建文件夹）和**分组合并**（事后修复被误拆的同一个人）。

---

## 功能特性

- **人脸检测 + 特征提取**：对视频抽帧，用 insightface 检出所有人脸，提取 512 维特征向量
- **质量过滤**：低置信度（det_score < 0.5）和过小的人脸（短边 < 32px）直接丢弃，保证特征可靠
- **视频内同人聚合**：同一人多帧向量按质量排序后聚簇、取平均，每人保留一个代表向量
- **主体簇匹配**：每组只保留"主体簇"（最主要的那个人）用于比对，避免次要/背景人脸污染
- **分组最少视频数**：同一人至少 `--min_videos` 个视频才创建文件夹；不足的留在原地（记入 `pending.txt`）
- **增量分类**：`face_gallery.npz` 保存人物特征库，新视频自动匹配已有分组
- **断点续跑**：`progress.txt` 记录已处理视频，中断后重跑自动跳过
- **特征缓存**：`emb_cache/` 缓存每个视频的向量，重复运行时秒过
- **分组合并工具**：`merge_groups.py` 事后合并被误拆的同一个人分组（纯 numpy，无重型依赖）

## 环境要求

- Windows（脚本针对 Windows 编码做了处理，其他平台也可运行）
- Python 3.12（uv 管理）
- GPU：支持 DirectML 的 NVIDIA GPU（本项目用 onnxruntime-directml，无需安装 CUDA Toolkit）

### 安装

```bash
# 初始化项目并安装依赖
uv sync
```

依赖：`insightface`、`onnxruntime-directml`、`opencv-python`、`numpy`。

首次运行会自动下载模型 `buffalo_l`（约 340MB）到 `~/.insightface/models/`。

## 快速开始

```bash
# 处理 D:/videos 下的所有视频，输出到 D:/videos\groups
uv run python main.py "D:/videos"

# 带日志文件（推荐，便于查看进度）
uv run python main.py "D:/videos" --log "D:/videos\run.log"
```

运行后 `D:/videos\groups` 下会生成：

```
groups/
├── group_1/          # 同一人的视频（文件夹名可自行重命名，如 "张三_1"）
├── group_2/
├── group_3/
├── emb_cache/        # 特征缓存（npy 文件）
├── face_gallery.npz  # 画廊：每个分组的人脸代表向量
├── progress.txt      # 断点续跑进度记录
├── pending.txt       # 待移动视频列表（分组未达 min_videos，暂时留在原地的）
└── group_report.csv  # 分组报告（视频 -> 分组 对照表）
```

## main.py 参数详解

### 基本参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `input_dir` | （必填） | 视频所在目录，脚本会扫描其中所有常见格式视频文件（mp4/mov/avi/mkv 等） |

### 处理参数

#### `--frame_interval`（默认 `2.0`）

**抽帧间隔（秒）**：每间隔多少秒取一帧做人脸检测。

- 视频仍从头到尾完整读取，只是抽帧变稀疏，处理时间 ≈ 视频时长 / 间隔
- `2.0` = 每 2 秒取 1 帧；`1.0` = 每 1 秒取 1 帧（更密，更慢）
- 间隔越大越快，但太大会漏掉短暂出现的人脸。建议 `1.0 ~ 3.0`

#### `--max_faces`（默认 `10`）

**早停阈值**：累计检出多少帧人脸后**提前停止**该视频。

- 单人/双人视频通常前几十帧就有足够人脸，无需跑完整视频
- `10` = 累计检出 10 帧人脸就停止该视频；`0` = 不限，跑完整视频
- 搭配 `--frame_interval` 可显著加速长视频
- 注意：统计的是"累计检出人脸帧数"，双人视频每帧 +2，会比单人更快达到阈值
- 视频都很短（<30 秒）可设 `0` 不限，反正跑完也快

#### `--min_videos`（默认 `2`）

**分组最少视频数**：某个分组至少多少个视频才创建文件夹并移动。

- 同一人 ≥ `min_videos` 个视频 → 创建 `group_XXX` 文件夹并移动
- 不足 → 视频留在原地，记入 `pending.txt`，等以后有同人新视频时一起补移
- 已存在的分组文件夹（历史批次已建立）不受此限制，新视频直接移入
- `1` = 每个视频都移动（恢复旧行为）

#### `--sim_threshold`（默认 `0.5`）

**匹配画廊的余弦相似度阈值**：判断"视频里的一张脸向量和分组里某个向量是不是同一个人"。

- 余弦相似度 ≥ 阈值 → 认为是同一人
- 同一个人跨视频相似度通常 `0.5~0.7`，不同人通常 `< 0.3`
- **调低**（如 `0.45`）：更宽松，减少"同一人拆成多人"；风险是可能误并不同人
- **调高**（如 `0.55`）：更严格，减少误并；风险是同一人拆成多组
- 以 `0.5` 起步，观察分组结果微调

#### `--video_match_ratio`（默认 `0.5`）

**匹配占比要求**：视频整体要归入某组，需要多少比例的向量"达标"。

- 视频检出 N 个向量，其中相似度 ≥ `sim_threshold` 的向量占比需 ≥ 此值
- 例：视频 4 个向量，3 个匹配上（75% ≥ 50%）→ 归入该组；只有 1 个（25%）→ 不归入
- 作用：**防止污染累积**——避免视频"只蹭到组里一个噪声向量"就整体吸入，导致不同人混进同一组
- 建议保持 `0.5`；若发现分组过碎可调低，过杂可调高

> **区分两个阈值**：`sim_threshold` 管"单张脸像不像（向量对）"，`video_match_ratio` 管"整个视频是不是这个组的人（整体比例）"。

#### `--cluster_threshold`（默认 `0.5`）

**组内主体簇聚类阈值**：组内两张人脸相似度超过该值算同一个人，用来找出每组最主要的人（排除混入的次要人脸/背景人脸）。

#### `--dedup_threshold`（默认 `0.5`）

**视频内聚合阈值**：同一视频里相似度超过该值的多张脸视为同一人，取其**平均向量**作为该人的代表（比单帧稳定）。

#### `--min_det_score`（默认 `0.5`）

**人脸检测置信度下限**：低于该值的模糊脸/误检脸直接丢弃（质量过滤）。

#### `--min_face_size`（默认 `32`）

**人脸最小尺寸**：bbox 短边小于该像素数的太小的人脸丢弃（小脸 embedding 不可靠）。

#### `--no_face_window`（默认 `5`）

**无人脸段判定窗口**：连续多少次采样都没有"通过质量过滤的人脸"，判定进入无人脸段。

- 例如默认 `5`：连续 5 次采样（如每 2 秒一次 → 约 10 秒）都没检到合格人脸
- 对转场、空镜、黑屏等无人脸镜头段有效

#### `--skip_seconds`（默认 `10`）

**无人脸段跳过的秒数**：判定进入无人脸段后，一次性向后跳过该秒数再继续采样。

- 例如默认 `10`：跳过 10 秒，避免逐帧检测无人脸的段落
- 与 `--no_face_window` 配合：`no_face_window` 决定"何时判定无人脸段"，`skip_seconds` 决定"跳过多远"
- 碰到人脸后计数清零，恢复正常采样

#### `--top_k`（默认 `3`）

**匹配打分方式**：与候选组匹配时，取最像的多少张人脸求**平均相似度**（比只看最像的 1 张更稳）。

#### `--margin`（默认 `0`）

**匹配置信度差**：第一候选与第二候选的得分差不足该值时，判定为边界情况、不归组（减少误并）。`0` = 关闭。

### 输出参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--output_dir` | `input_dir/groups` | 分组输出目录 |
| `--report` | `output_dir/group_report.csv` | 分组报告 CSV 路径（视频 → 分组对照） |
| `--gallery` | `~/.face_video_group/face_gallery.npz` | 画廊文件路径（人物特征库，默认在用户目录，跨目录共享） |
| `--progress` | `output_dir/progress.txt` | 断点续跑进度文件路径 |
| `--cache_dir` | `output_dir/emb_cache` | 特征缓存目录 |

### 运行参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--device` | `0` | onnxruntime 设备 id，`0` = GPU（DirectML），`-1` = CPU |
| `--log` | 无 | 日志文件路径，设置后日志同时写入文件 |

## 常见用法组合

```bash
# 单人/双人视频 + 长视频提速：2 秒抽帧 + 检出 20 帧人脸即停
uv run python main.py "D:/videos" --frame_interval 2.0 --max_faces 20

# 同一人经常被拆成多人：降低匹配阈值
uv run python main.py "D:/videos" --sim_threshold 0.42

# 不同人经常被误并：提高匹配阈值 + 提高匹配占比 + 开启 margin
uv run python main.py "D:/videos" --sim_threshold 0.55 --video_match_ratio 0.6 --margin 0.05

# 画质差/模糊脸多：提高质量过滤门槛
uv run python main.py "D:/videos" --min_det_score 0.6 --min_face_size 48

# 新增视频增量处理（旧视频已处理会跳过）
uv run python main.py "D:/videos" --log "D:/videos\run.log"
```

## 分组命名与重命名

分组文件夹默认命名为 `group_1`、`group_2`……（不定长数字，永不溢出）。

**你可以随意重命名分组文件夹**，脚本通过**数字后缀**识别分组：

```text
group_1        -> 张三_1        （合法，脚本识别为分组 1）
人物A_1000     -> 人物A_1000    （合法，识别为分组 1000）
```

重命名后，画廊和后续处理仍能正确关联到该分组。报告 CSV 中的 `group` 列显示的是文件夹实际名称。

### 人物名映射（person_names.json）

为了让名字"存一处、自动沿用"，可以编辑 `~/.face_video_group/person_names.json`：

```json
{
  "4": "张三",
  "5": "李四",
  "6": "Ella-Rose"
}
```

- 键是**人物 ID（数字）**，值是人名（**可含 `-`、空格等特殊字符**，放在前缀不影响识别）
- 文件不存在时脚本静默跳过，不报错
- 每次运行 main.py 都会**自动对齐重命名**：`group_4` → `张三_4`，即使没有新视频也会生效
- 新建分组时若该人物有人名，直接用 `人名_id` 命名
- 合并分组（merge_groups.py）时会自动清理被合并人物的名字
- 人名只影响文件夹名，不影响画廊匹配逻辑（识别仍靠数字 ID）

## 断点续跑与增量处理

- **断点续跑**：已处理并移动的视频记入 `progress.txt`。中断后重跑，已处理视频自动跳过（日志显示 `已处理，跳过`）
- **增量处理**：处理过的视频已移入分组文件夹（不在输入目录），新增视频放进 `input_dir` 再跑即可，只处理新视频
- **待移动补移**：未达 `--min_videos` 的视频留在原地并记入 `pending.txt`，下次有同人新视频时自动一起补移
- **缓存加速**：视频的向量缓存在 `emb_cache/`，重新处理时直接读缓存
- **进度记录键** = 文件路径 + 大小 + 修改时间；特征缓存键还包含抽帧/过滤/聚合参数。视频内容或参数变了会自动失效重新处理

> 若想强制重跑某个分组，删除对应记录：清空 `progress.txt`（全部重跑）或删除指定记录。

## 画廊（face_gallery.npz）

画廊是**人物特征库**，存储"人物 ID → 该人物的特征向量"。它是判断"新视频属于哪个人"的依据。

### 画廊存什么

- 键 = 人物 ID（gid，数字编号，如 `4`）
- 值 = 该人物的 512 维特征向量矩阵
- **不存视频信息**（不存文件名、路径、视频内容）

### 人物特征是否固定

**固定**。insightface 的 embedding 是**确定性的**——同一张脸的 `normed_embedding` 固定不变，与用什么参数提取无关。性别过滤（`--gender`）只决定"**哪些脸**被收进画廊"，**不改变每张脸的特征值**。

### 换参数（如 --gender）对画廊的影响

- **已有的人物特征不变**，画廊内容不变
- 性别过滤只是改变"**新视频里提取哪些脸**"——用 `--gender female` 时，新视频只提取女性脸去匹配画廊里的女性组
- **画廊无需重建**，新视频追加到匹配到的组即可
- 唯一需要注意的是缓存：缓存键包含参数，换参数后旧缓存失效会重新提取（但结果相同，只是白算一遍）

### 画廊与分组文件夹的关系

- gid 同时是"人物 ID"和"分组文件夹编号"（`group_4` 的数字后缀）
- **文件夹名可以随意重命名**（如 `张三_4`），脚本通过数字后缀识别，人物 ID 不变
- 报告 CSV 中的 `group` 列显示的是文件夹实际名称

### 画廊默认位置

画廊默认存放在用户目录 `~/.face_video_group/face_gallery.npz`，跨目录/跨盘处理时**默认共享同一个画廊**。用 `--gallery` 可指定其他位置。

## merge_groups.py：分组合并工具

当"同一个人被识别成多人"时，用于**事后合并**被拆散的分组。只做后处理（移动视频 + 合并画廊向量），不重新做人脸检测。基于纯 numpy，**不加载 cv2/insightface/onnxruntime**，启动快。

### 用法

```bash
# 先看有哪些疑似同一人的组对（不执行合并）
uv run python merge_groups.py "D:/videos\groups" --dry_run

# 逐对确认合并
uv run python merge_groups.py "D:/videos\groups"

# 自动合并所有候选（不确认）
uv run python merge_groups.py "D:/videos\groups" --auto
```

### 参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `output_dir` | （必填） | groups 输出目录 |
| `--gallery` | `~/.face_video_group/face_gallery.npz` | 画廊文件路径（与 main.py 一致） |
| `--sim_threshold` | `0.5` | 向量对相似度阈值（与 main.py 一致） |
| `--coverage_ratio` | `0.5` | 小分组主体被大分组主体覆盖的比例下限 |
| `--strong_match_threshold` | `0.55` | 兜底强匹配阈值：即使覆盖比例不足，最大相似度超过该值也提示合并 |
| `--cluster_threshold` | `0.5` | 组内主体簇聚类阈值 |
| `--dry_run` | `false` | 只列出疑似组对，不执行合并 |
| `--auto` | `false` | 自动合并所有候选，跳过逐对确认 |
| `--cleanup-orphans` | `false` | 清理无文件夹的残留分组（默认关闭，避免误删纯 pending 分组） |

### 判定逻辑

每组的向量先提取**主体簇**（组内互相最相似的主要人群），再两两比较：

- **最大相似度** ≥ `--sim_threshold`
- 且（**小分组主体被大分组覆盖比例** ≥ `--coverage_ratio` **或** 最大相似度 ≥ `--strong_match_threshold`）

判定为疑似同一人。组大小不对称时（如 3 个向量 vs 88 个向量），全体占比会被稀释，"小分组主体整体被大分组吸收"更能说明是同一人。

调整建议：
- 误报太多（不同人被判同人）→ 调高 `--coverage_ratio` 到 `0.7` 或调高 `--sim_threshold`
- 漏报（同人没被发现）→ 调低 `--strong_match_threshold` 到 `0.5`

### 合并行为

- 视频多的组保留，另一组视频移入（重名文件自动跳过不覆盖）
- 画廊向量合并，被合并的空文件夹删除
- 每合并一对立即保存画廊，并重新计算候选直到没有新疑似组对（保证传递关系不漏）

> **关于 `--cleanup-orphans`**：默认不清理"无文件夹的分组"——因为纯 pending 分组（视频未达 min_videos 未移动）本就没有文件夹，自动清理会误删其累积向量。仅在明确需要清理已合并残留时开启。

## 常见问题（FAQ）

**Q：为什么同一个人的视频被拆成多个分组？**
A：匹配是逐视频贪心且不可回溯的——新视频只和"当时已存在的组"比较，处理顺序可能打断同人关联。用 `merge_groups.py` 事后合并即可。

**Q：为什么两个组相似度很高，分组时却没放一起？**
A：分组时是"视频向量 vs 组向量"的匹配（受阈值和占比约束）；合并工具是"组 vs 组"全局回看，能发现被顺序打断的关联。

**Q：视频处理得很慢怎么办？**
A：脚本已用 seek 跳帧解码（不再顺序解码全部帧）。再提速：加大 `--frame_interval`、用 `--max_faces` 早停、降低 `--min_det_score` 减少无效检测。

**Q：运行中能手动移动视频吗？**
A：不建议。可能把视频误标为"无人脸"或导致找不到文件。等跑完再整理。

**Q：没有 GPU 能跑吗？**
A：能，加 `--device -1` 用 CPU，但会慢很多。脚本默认走 DirectML（GPU）。

**Q：为什么有的视频没被移动，还留在输入目录？**
A：两种情况：① 视频未检出人脸；② 视频分到的组本轮视频数不足 `--min_videos`（默认 2），记入 `pending.txt` 留在原地。以后有同人新视频进来时，会一起补移。
